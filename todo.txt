Assets review TODO - D&D game
=============================

Laatste update: 2026-06-04
Repo: https://github.com/japiohopman/artificer/tree/main/public/assets
Scope: public/assets, met /toril/ en /animals/ genegeerd zoals eerder gevraagd.

Korte conclusie
---------------
De assets staan er duidelijk beter voor dan bij de eerste review. De basis is goed genoeg om een D&D game op te bouwen: er is een herkenbare atlas-structuur, veel domeinen hebben json/images, en equipment heeft inmiddels een vrij complete set met data plus afbeeldingen.

De grootste resterende klus is niet "alles mooier indelen", maar zorgen dat de game betrouwbaar data kan laden. Voor een D&D game worden assets eigenlijk content-data: equipment, spells, enemies, maps, sounds en UI moeten als een mini-database werken. Daarom zijn schema's, indexes en padvalidatie belangrijker dan cosmetische map-perfectie.

Performance en build
--------------------
[ ] Voeg size budgets toe.
    Equipment images zijn vaak rond 1-1.8 MB per stuk. Dat is mooi voor kwaliteit, maar zwaar voor een game.
    Startvoorstel:
    - WEBP/PNG warn boven 1 MB
    - WEBP/PNG fail boven 2.5 MB tenzij allowlisted
    - JSON warn boven 250 KB
    - JSON fail boven 1 MB tenzij allowlisted
    - music/audio boven 5 MB alleen lazy-load/streamen

Belangrijk advies
-----------------
Laat de mapindeling niet de game-logica bepalen. Voor een D&D game moet equipment vindbaar zijn op gedrag: weapon, armor, pack, slot, cost, rarity, damage, proficiency, shop category, loot category. Of de JSON fysiek in een platte map staat of in submappen is minder belangrijk zolang je indexes en schemas betrouwbaar zijn.
